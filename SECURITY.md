# Security Policy

## Project maturity

This project is experimental and must not be treated as a production authorization boundary or used for high-impact autonomous actions.

## Reporting vulnerabilities

Use GitHub Private Vulnerability Reporting for sensitive reports. Do not open a public issue for vulnerabilities that could enable unauthorized access, data exposure, policy bypass, supply-chain compromise, or unsafe agent execution.

Include:

- affected commit or version
- prerequisites and impact
- reproduction steps or proof of concept
- suggested mitigation, if known

## Security scope

Especially relevant reports include:

- authority expansion or approval bypass
- confused-deputy behavior
- prompt or memory injection
- skill poisoning or provenance forgery
- replay and idempotency failures
- secrets exposure
- unsafe default capabilities
- outcome-verification spoofing
- dependency or build-chain compromise

No bug bounty is currently offered.
