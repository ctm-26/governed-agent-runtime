# Governance

## Current phase

The project is founder-led during the pre-1.0 research phase. Chris Moore (`@ctm-26`) is the initial maintainer.

## Decision mechanisms

- Small reversible changes use pull requests.
- Architectural decisions use ADRs.
- Specification changes use RFCs.
- Security-sensitive changes require a threat-model update and negative tests.
- Claims of novelty or performance require documented evidence.

## Maintainer responsibilities

Maintainers protect the project charter, review provenance and licensing, keep decisions auditable, disclose conflicts, and avoid presenting hypotheses as established facts.

## Becoming a maintainer

Maintainer status should require sustained, high-quality contributions across review, specification, implementation, research, or security. The process will be formalized before the first stable release.

## Authority over the project

Repository permissions are not evidence that a technical claim is correct. Technical decisions remain contestable through evidence, tests, and RFC review.
